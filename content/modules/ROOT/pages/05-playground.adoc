= Module 5: Test the Model Playground

_Estimated time: 10 minutes_

In this module you will access the Red Hat OpenShift AI dashboard, locate the TinyLlama model endpoint, and test prompts directly through the model playground -- bypassing AnythingLLM and the RAG pipeline.

== Open the OpenShift AI Dashboard

The Red Hat OpenShift AI (RHOAI) dashboard provides a centralized view of deployed models, serving runtimes, and inference endpoints. Open it using the link in the header bar of this lab environment, or navigate to:

== Navigate to Model Serving

Once in the RHOAI dashboard:

1. Click *Model Serving* in the left navigation menu
2. You should see the TinyLlama model listed as a deployed model
3. Note the *Status* column -- it should show the model as ready and serving

The dashboard shows key information about the deployment:

* *Model name:* `TinyLlama/TinyLlama-1.1B-Chat-v1.0`
* *Serving runtime:* vLLM (CPU)
* *Endpoint URL:* The internal and external URLs for the inference API

== Access the Playground

Click on the TinyLlama model entry to open its detail view. Look for the *Playground* or *Test* section where you can interact with the model directly.

The playground provides a simple chat interface that sends requests straight to the vLLM endpoint. Unlike AnythingLLM, there is no RAG -- no document retrieval, no vector search. This gives you the raw model output.

== Test Prompts

Try the following prompts in the playground:

=== General Knowledge

----
Explain what a compliance officer does in a bank.
----

Compare this response to what you received from AnythingLLM in Module 4. Without RAG context, the model relies entirely on its training data. For a 1.1B parameter model, the answers will be reasonable but less specific.

=== Structured Output

----
List five steps for onboarding a new employee at a financial institution.
----

Observe how well the model follows the instruction to produce a numbered list. Small models can struggle with structured output formats.

=== Technical Question

----
What is the difference between CPU and GPU inference for large language models?
----

This is a topic the model likely has good training data for. Notice the difference in quality compared to the domain-specific HR questions.

== Check the Endpoint Directly

You can also test the model endpoint from the terminal using curl:

[source,bash,role="execute",subs="attributes+"]
----
export VLLM_URL=$(oc get route vllm-server -n {project_name} -o jsonpath='https://\{.spec.host\}')
curl -s $\{VLLM_URL\}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    "messages": [
      {"role": "system", "content": "You are a helpful HR assistant for a banking institution."},
      {"role": "user", "content": "What training records must we maintain for FINRA compliance?"}
    ],
    "max_tokens": 200,
    "temperature": 0.7
  }' | python3 -m json.tool
----

Notice the response includes a `usage` block showing the number of prompt tokens and completion tokens. This is useful for understanding model utilization and planning capacity.

== Playground vs AnythingLLM

Here is a summary of the two access paths you have explored:

[cols="1,1,1"]
|===
| Feature | Playground | AnythingLLM

| *Document retrieval*
| No
| Yes (RAG)

| *Context grounding*
| Training data only
| Retrieved documents + training data

| *Interface*
| RHOAI Dashboard
| Standalone workbench

| *Best for*
| Model evaluation, API testing
| End-user Q&A, document-grounded chat
|===

Both paths call the same vLLM endpoint running on {intel_platform} CPU. The difference is whether the prompt includes retrieved document context.
