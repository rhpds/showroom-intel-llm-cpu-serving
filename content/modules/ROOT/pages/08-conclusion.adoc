== The Key Insights

* *CPU inference is viable for small models at low concurrency.* TinyLlama 1.1B runs on standard {intel_platform} servers with no GPU. For a team-sized HR assistant, this is all you need.
* *KServe separates the how from the what.* ServingRuntime defines how to run models. InferenceService defines which model to deploy. This separation makes model serving manageable at scale.
* *ModelCar eliminates cold start pain.* Model weights as OCI images mean fast, reproducible, air-gap-friendly deployments.
* *RAG does not make the model smarter -- it gives the model better information.* The same 1.1B model gives materially different answers with and without retrieved context.
* *Know your limits.* CPU inference works for small models, short outputs, and low concurrency. Know when to scale horizontally and when to move to GPU.

== Next Steps

Now that you understand how to build a CPU inference stack, consider:

* *Try a larger model* -- swap TinyLlama for a 3B or 7B model by updating the InferenceService `storageUri` and resource limits. Observe the latency-quality tradeoff.
* *Add your own documents* -- upload your organization's actual HR policies, handbooks, or regulatory documents into AnythingLLM.
* *Scale for teams* -- add replicas to the InferenceService for higher concurrency. Add authentication to AnythingLLM for multi-user access.
* *Explore Llama Stack* -- the quickstart also includes a Llama Stack service for agentic workflows and tool calling.

oc delete svc anythingllm -n {project_name}
oc delete route anythingllm -n {project_name}
oc delete secret anythingllm-config -n {project_name}
