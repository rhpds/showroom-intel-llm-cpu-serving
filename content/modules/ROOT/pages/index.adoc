= Build a CPU Inference Stack from Scratch
:navtitle: Welcome

In this lab you will *build* a complete LLM inference and RAG system on {intel_platform} CPUs -- component by component.
You will not deploy a Helm chart and click around.
You will construct every Kubernetes resource, understand every configuration decision, and walk away knowing how to build CPU-based AI serving from scratch.

== The Scenario

Your organization wants to serve an LLM internally without GPU hardware.
The model must answer employee questions grounded in real documents -- an HR assistant backed by Retrieval-Augmented Generation.
You will build this on the {intel_platform} processors already running in your OpenShift cluster.

== What You Will Build

By the end of this 90-minute lab, you will have constructed four components and wired them together:

[cols="1,2,2",options="header"]
|===
|Component |What It Does |Technology

|*vLLM Serving Runtime*
|Defines how to run LLMs on CPU inside OpenShift AI
|KServe ServingRuntime + vLLM CPU image

|*Model Endpoint*
|Deploys TinyLlama 1.1B and serves it via an OpenAI-compatible API
|KServe InferenceService + ModelCar OCI pattern

|*RAG Frontend*
|Connects a chat workbench to the model endpoint with document retrieval
|AnythingLLM + LanceDB

|*Document Pipeline*
|Loads, chunks, and embeds documents into the vector store
|AnythingLLM API + embedding model
|===

== Prerequisites

* Access credentials for your OpenShift cluster (provided in the demo platform)
* A terminal (the *Bastion* tab in the showroom)
* No GPU hardware required -- that is the point
